03 / Approach
Approach / four habits

Small steps. Working software.

How I like to work, whether it’s a weekend project or a ticket on a team.

0 x 0
<SectionHead title="Approach" />
01

Understand

Ask what problem we’re solving, and for whom, before touching the keyboard. Most bugs start as misunderstandings.

ask early / write it down
0 x 0
<Step n={1} />
02

Build small

Get the thinnest version working end to end, then grow it. Something running beats something perfect.

ship thin / iterate
0 x 0
<Step n={2} />
03

Make it clear

Rename, simplify, add the test. A teammate (or me in six months) should be able to follow the code.

readable / tested
0 x 0
<Step n={3} />
04

Share, then learn

Ask for review, read the feedback twice, and write down what I’d do differently next time.

review / reflect
